## 物理模型

```
θ″ = −(g/L)·sin θ − γ·θ′
```

- 简谐（小角）近似下 `θ″ ≈ −(g/L)·θ`，即固有角频率 `ω₀ = √(g/L)`
- 采用**半隐式欧拉法**积分，固定子步长 1/600 s，与帧率解耦
- 像素与物理量换算：固定 `200 px = 1.00 m`，故 `L_m = L_px / 200`
- 阻尼约定：`γ = 60·b`，`b ∈ [0, 0.010]` 为每 1/60 秒损失的速度比例

## 验证结果

| 项目 | 理论 | 实测 | 误差 |
| :--- | :--- | :--- | :---: |
| 周期（L=1 m, g=9.8, θ₀=45°） | 2.085 s（含大振幅修正） | 2.087 s | 0.1% |
| 周期（g=25, L=200 px） | 1.257 s | 1.257 s | 0% |
| 无阻尼能量漂移（20 s） | 有界 | ±0.25% | — |
| 阻尼衰减率 `b=0.010` | 0.300 s⁻¹ | 0.3013 s⁻¹ | 0.4% |
| 阻尼衰减率 `b=0.005` | 0.150 s⁻¹ | 0.1505 s⁻¹ | 0.3% |
| 阻尼衰减率 `b=0.002` | 0.060 s⁻¹ | 0.0606 s⁻¹ | 1.0% |

## 实验报告 / 心得

### 难点一：物理与画面的单位不一致

摆长用像素（100~350 px）表示，重力却是 `9.8 m/s²`。若直接把两者塞进
`g/L`，周期会算成 28 秒，摆球几乎不动。解决办法是引入固定比例
`200 px = 1.00 m`，让 `g/L` 始终得到一个无量纲的比值 —— 这样既满足
"滑块量程是像素"的需求，又保证物理正确（实测周期 2.007 s）。

### 难点二：阻尼系数的量纲选择

阻尼系数 `b` 若直接作为 `γ`(s⁻¹) 使用，`b=0.010` 对应时间常数 `τ = 2/γ = 200 s`，
数值上"有阻尼"，肉眼却完全看不出衰减。取 `γ = 60·b` 后，
`b=0.010 → τ=3.3 s`，正好落在"能明显看出自然衰减"的区间，
并且用转折点振幅做 `ln A ~ t` 线性拟合可以精确标定衰减率。

### 难点三：数值积分的稳定性

用显式欧拉法直接积分会持续积累能量、振幅缓慢发散。改用**半隐式欧拉**
（先更新 `ω` 再更新 `θ`）并把子步长固定到 1/600 s 后，无阻尼情况下
20 s 能量漂移有界于 ±0.25%。

帧率无关性也做了实测：用 CDP 把 CPU 限流，模拟出 61 / 44 / 13 FPS
三种帧率，分别拟合转折点振幅的衰减率，得到 0.1505 / 0.1506 / 0.1500 s⁻¹，
极差仅 0.0006 s⁻¹（相对 0.4%），与设计值 `30b = 0.150` 吻合。

> 这一步一开始测错了两次：第一次拿不同仿真时刻的 θ 直接比较，
> 第二次在 61 FPS 下用 `setInterval` 采样 —— 但 HUD 每帧才更新一次，
> 相邻采样值大量重复，被我的极值检测误判成 465 个"转折点"。
> 教训是：**测量采样率必须与被测量的刷新率匹配**，
> 否则测的是采样假象而不是物理。

### 一条经验

调参时改变摆长或重力，相当于外部对系统做功，总能量会瞬间跳变。
如果沿用旧的能量基准，HUD 的"能量漂移"就会出现虚假的大幅偏差。
所以每次调参和复位都重置能量基准 —— **先想清楚这个数字在跟谁比较**，
比调参数本身更重要。
